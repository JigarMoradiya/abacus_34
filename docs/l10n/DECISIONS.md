# Decisions taken while the owner was away (please review when back)

Each line: what was decided, why, and how to change it.

1. **Test copy next to the Play app.** The phone now holds the Play build (177, installed 2026-11-03 18:27), which must not be touched. Test builds use `-Pl10nCopy` (id `com.abacus.puzzle.l10n`, label "Abacus L10n"). Needs a gated line in `app/build.gradle.kts`, a manifest placeholder for the first FileProvider authority, and a local-only `app/src/dev1Debug/google-services.json` (not committed). Purchases cannot be tested in the copy.
2. **Local commits per verified module, no push.** Keeps every module recoverable. Squash or drop whenever you like.
3. **Portuguese** uses one folder `values-pt` with Brazilian wording (also serves Portugal).
4. **Language names** are shown in their own language and are not translated (`language_names.xml`, `translatable="false"`).
5. **Language order (owner, 2026-11-03): left-to-right languages first, Arabic last.** Wave 1 = fr es pt tr ru, wave 2 = ja th (left to right, need fonts and Thai line breaking), Arabic (right to left) is its own pass at the end (M21). Every module translates and checks all left-to-right languages together. Until the right-to-left pass is done `LanguageManager.RTL_READY = false`: the picker never offers Arabic, an Arabic phone gets English, and `apply.py` does not write `values-ar` (use `apply.py --with-ar` then). Arabic texts stay in the master files so nothing is lost. To check at M21: the Play build already mirrors its layout on an Arabic phone (supportsRtl), so the Arabic pass starts from that.
6. **Left/right and spacing are checked in every module.** Each module runs `tools/l10n/scan_layout.py` (absolute left/right, non-mirrored arrows, x offsets, fixed widths on one-line text) and is looked at in the longest languages (fr ru pt tr, about 30-40% longer than English) plus the debug pseudo-locale `en-XA`. New code uses start/end, never left/right.
7. **Voice follows the app language.** Before, the voice was forced to `en_IN` for everyone and a saved voice was read back wrongly (tag `hi-IN` vs Gson `Locale`), so non-English voices fell back to English. Now: saved voice (read in every form) else the usual voice of the app language; English keeps `en-IN` as before.
8. **Full 149-route walk only at checkpoints** (after M5, M12, M17 and the end); each module is checked on its own routes with text dumps and one small contact sheet.
9. **Picker list:** the owner said it is fine to show every language in Settings. The Remote Config key `enabled_languages` stays as a kill switch (empty = English only), so at release it can simply list all languages. Debug builds show all (except Arabic until M21).
10. **Number words are our own code, not Android's.** The ICU class `RuleBasedNumberFormat` is not part of the public SDK (only a hidden class on the phone), so `NumberWords.kt` spells numbers for fr es pt tr ru ja th and is unit tested against that phone's data (`app/src/test/resources/number_words_golden.tsv`, 621 numbers per language). Deliberate difference: Japanese writes 二万一千 (ICU leaves out the 一). English keeps its own Indian words (lakh, crore) from the resource strings, which are now `translatable="false"`. Arabic is added in the right-to-left pass.
11. **Spoken words follow the voice's language**, not only the app language: `TextToSpeechManager.words()/phrase()/tableLine()` use the language of the chosen voice when the app has it, else English (a Hindi voice still gets English words). On screen the words follow the app language. Zero is now said ("Zero"), before it was an empty string.
12. **Gotcha for every module:** on Android 12 and older the application context (the one view models hold) does not follow the language picked inside the app, only the activity does. Text that a view model or helper builds from `context.getString()` must use `context.inAppLanguage()` (or `withLanguage(tag)`), both in `LanguageManager.kt`.
13. **Place-value names on the rods** (Ones ... Lakhs, Ten Lakhs, Crores) move to M6 (Free Mode and the abacus strips). Plan: English keeps the Indian names; other languages use their own international names for 10^4 / 10^5 / 10^6 (for example fr "Dix mille / Cent mille / Million", ja 万 / 十万 / 百万, th หมื่น / แสน / ล้าน), kept short because the labels are tiny.
14. **Dates are locale-safe.** All text the app parses or sends to the server (report filters, server timestamps) now uses `Locale.US`; before it used the phone's default locale, which on a Thai phone writes Buddhist years (2569) and on an Arabic phone Arabic-Indic digits. Text a person reads uses `DateTimeUtils.displayLocale()` (app language, Gregorian calendar, digits 0-9) and the usual date pattern of that language; the words "Today at / Yesterday at / At" are strings (`date_today_at` ...). English output is unchanged.
15. **HTML in strings.** A string whose English source has real `<b>` tags is written with real tags in the translations; a string whose English source holds the HTML as text (`&lt;b>`, used when the code runs it through `htmlToAnnotatedString`) is written as text. `apply.py` decides from the English source. The What's-learning bullets are the second kind; I also fixed a stray unclosed `<b>` in the English text of the first bullet.
16. **FAQ and What's-learning lists are built in the app language** (`context.inAppLanguage()`), so they follow the picked language on Android 12 and older too.
17. **Free-trial popup pictures are drawn in code.** `ic_free_trial_3/7.png`, `free_trial_day_left.png` and `ic_now.png` had English words baked in, so the badge, the "days left" pill and the "NOW" sticker are now Compose shapes with translated text (same colours). The old PNG files stay in the project, unused by this screen. The digit pictures (`ic_number_0..6`) have no words and stay.
18. **Plan names and prices.** Plan duration words (Weekly, Monthly, Yearly, Lifetime ...) and the per-period suffixes are strings. Prices, intro-offer prices and the currency come from Google Play through RevenueCat and are shown as the store gives them. Recommended: a quick native skim of the paywall texts (M8) before the release, because they decide the purchase.
19. **Arabic (right to left), module M21.** `LanguageManager.RTL_READY = true`; layouts mirror (start/end), the abacus, the answer bars and the number pads sit in a left-to-right island (`LtrIsland`, wrapped around the public abacus / answer-bar composables), directional icons are the AutoMirrored versions, and every text style of the app (`AbTypography.fixed`, `AppTypography`) carries `TextDirection.ContentOrLtr` so digits, signs and equations read left to right while Arabic words run right to left. Arabic texts wrap math fragments ("(1–9)", "5 + 1 = 6") in LRE ... PDF marks (`tools/l10n/ar_bidi.py`). Navigation arrows in strings are written for the reading direction ("التالي ←", "→ رجوع"). Arabic number words are our own (`NumberWords.ar`, masculine nominative). Digits are always 0-9.
20. **Server text per language.** `RemoteText` reads `<key>_<lang>` first (video list, paywall social proof, update notes, login note), else the English key; the console values are the owner's job (`docs/l10n/REMOTE_CONFIG.md`).
21. **Notifications** (streak, weekly, free-week) are built inside the workers with `context.inAppLanguage()`; channel names are translated too.
